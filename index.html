Backtracking: try, fail, undo, try again

Backtracking builds a solution one choice at a time and abandons a path the moment it can’t work. Pick a size below and watch a depth-first search walk the tree of choices.

Each node is a partial arrangement of letters. The search goes as deep as it can, and when a branch breaks the rule (or finishes) it steps back up and tries the next sibling. Turn pruning off to see the full permutation tree, which has n! leaves. That growth is why n stops at 5 here: with 26 letters the tree would have about 4×10²⁶ leaves.

Three counting ideas show up in every backtracking problem. A permutation orders all n items (n! ways). An arrangement orders only k of them (n!/(n−k)! ways). A combination picks k items and ignores order (n!/(k!(n−k)!) ways). For n=5 and k=2 that is 120, 20 and 10. Project overview

Abstract and objectives

Abstract. This project investigates backtracking as a depth-first search technique for solving problems defined by choices and constraints. It combines interactive visualizations with implementations of classic problems, including N-Queens, Sudoku, maze path finding and Subset Sum. The demonstrations show how a partial candidate is extended, tested and undone when it cannot lead to a valid solution.

Project objectives

  • Explain the state-space search model and the choose–explore–un-choose cycle.
  • Implement backtracking for several constraint-based problems.
  • Visualize valid choices, rejected branches and backtracking steps.
  • Evaluate how search effort changes with problem size and pruning.
  • Relate the method to AI planning and robotic task sequencing.

Scope and method

The project uses deterministic constraints and depth-first exploration. Interactive examples are intended to make the algorithm observable; the performance experiment measures node counts and elapsed time for N-Queens. The results describe these implementations and test cases, not every possible backtracking algorithm.

Central idea: a partial solution is retained only while it remains possible to extend it into a valid complete solution. Pruning is correct only when a rejected partial state cannot lead to any valid solution.

How it works

Backtracking is a systematic way to search for solutions to problems made of a sequence of choices. It explores a tree of partial solutions in depth-first order. At each node it asks whether the partial solution can still lead somewhere; if not, it cuts that whole subtree off. Three verbs describe it: choose, explore, un-choose.



The C++ and Python tabs are a complete N-Queens counter that follows the same template: it prints 92 for n=8.


The pruning test is where the speed comes from. Brute force would check every complete candidate. Backtracking rejects a bad prefix once and skips every candidate that starts with it.







  
Formal description

  
Mathematical model of backtracking

  
A backtracking problem can be described by a state space, a set of candidate actions, constraints and a goal test. The algorithm searches a tree whose nodes are partial solutions.

  

    
StateA partial assignment that records the choices made so far.

    
CandidateA possible next choice that extends the current state.

    
ConstraintA rule that determines whether a partial assignment is still feasible.

    
Goal testA condition that identifies a complete valid solution.

  

  
Example: N-Queens

  
Represent a partial placement of queens as \(S=(c_0,c_1,\ldots,c_{r-1})\), where \(c_i\) is the column selected for row \(i\), and \(r\) is the next row to fill. Because the algorithm places one queen per row, only column and diagonal conflicts need to be checked against earlier rows.

  
For every pair of rows i ≠ j:
  cᵢ ≠ cⱼ                         (different columns)
  |cᵢ − cⱼ| ≠ |i − j|             (different diagonals)

  Initial state: S = ()
  Goal condition: r = n
  Transition: S' = S appended with candidate column c
  Reject a transition if either constraint is violated.

  
The search tries a candidate column, recursively explores the extended state, and removes that candidate when the recursive call returns. This removal restores the state so the next candidate can be tested.

The exact state representation and validity test depend on the problem. The same general structure can solve puzzles, scheduling problems and selected planning tasks.

A short history




1848 The eight queens puzzle appears in a German chess magazine, credited to Max Bergmann. Gauss later studied it; the full count of 92 solutions was settled soon after.


1950s The mathematician D. H. Lehmer coins the word “backtrack”.


1960 R. J. Walker publishes an early description of backtracking as a computer algorithm for combinatorial problems.


1962 The string-processing language SNOBOL is often cited as one of the first to build general backtracking into the language itself.


1965 Golomb and Baumert publish “Backtrack Programming”, generalizing the method.


1972 Prolog is created; backtracking becomes its core execution model.

Where it’s used




Puzzles and games
Sudoku, N-Queens, crosswords, knight’s tour, word search.


Constraint solving
Scheduling, timetables, map coloring, resource assignment.


Logic and SAT
The DPLL algorithm behind many SAT solvers is backtracking with smart pruning.


Languages and parsing
Prolog resolves queries by backtracking. Many regex engines backtrack when a match fails.


Combinatorial optimization
Branch and bound extends backtracking with a cost bound: prune any branch that can’t beat the best answer so far.


Robotics and planning
Task and motion planners search sequences of actions, undoing steps that lead to collisions or dead ends.









Pushing it further: AI, machine learning and robotics


Backtracking is more than a classroom trick. It is one of the oldest tools in AI, and the current push is to combine it with learning. First, the three terms people often mix up:




Artificial intelligence
The broad goal of building systems that do tasks that normally need human intelligence: reasoning, planning, perception, language. It includes rule and search-based methods as well as learning-based ones.


Machine learning
The part of AI where a system improves from data instead of following hand-written rules. It fits a model, such as a neural network, that generalizes statistically.


Robotics
Building machines that sense, decide and act in the physical world. It uses AI and ML, plus mechanics, control and electronics.




The key difference: backtracking is search. It is exact and rule-based: given the rules, it either finds a valid answer or proves none exists, but its cost can explode. Machine learning is approximate: it is fast and copes with messy data, but it comes with no guarantee that an answer obeys the rules. The strongest recent systems combine the two. A learned model guesses which branch looks promising, and the search checks that the result is actually valid.

Where backtracking appears in AI


    

  • Planning and constraint solving. Automated planners search sequences of actions and undo any step whose preconditions fail. Scheduling and configuration tools work the same way.
    • 

  • SAT and SMT solvers. Modern solvers use conflict-driven clause learning (CDCL): backtracking plus learning a new rule from each dead end, then jumping back several levels at once. They verify chips and software and also power planners.
    • 

  • Logic programming. Prolog answers queries by trying clauses in order and backtracking on failure.
    • 

  • Game AI. Minimax walks the game tree depth-first. Alpha-beta pruning cuts branches that cannot change the result, which is backtracking’s pruning idea applied to a two-player tree.
    • 

  • Reasoning with language models. Tree-of-Thoughts-style methods let a model propose several next reasoning steps, score them, and go back to an earlier step when a line of thought looks wrong.
    • 

  • Checking neural networks. Verification tools such as Reluplex and Marabou split on whether each ReLU unit is active or inactive, and backtrack when a case turns out to be impossible.
    • 

  • Learned guidance. NeuroSAT showed a network can learn to predict satisfiability; AlphaZero-style systems use a network to steer tree search. Both keep the search and improve how it picks branches.
    • 



Robotics


In task and motion planning, a robot first chooses a symbolic plan (grasp part A, place it, grasp part B). A motion planner then checks that each step is physically possible. If no collision-free motion exists, the planner backtracks and tries another grasp, another order, or another placement. Assembly sequencing and pick-and-place cell planning have the same shape: many ordered choices, many hard constraints.


How far can it go?


The limit is still exponential growth, so progress comes from searching smarter, not from waiting for faster hardware: better branch ordering (often learned), constraint propagation, clause learning, parallel search, and hybrids where a neural network proposes and a symbolic search verifies. The open challenge is keeping the guarantee of correctness while scaling to far bigger problems. Learning will not replace backtracking, and backtracking will not replace learning; each covers the other’s weakness.

Cost, and how to tame it


Worst case, backtracking is exponential: roughly bd nodes for branching factor b and depth d, or n! for permutations. Pruning rarely changes that worst case, but it often shrinks real running time by orders of magnitude. Tools that help:


    

  • Check constraints early, as soon as a choice makes them fail.
    • 

  • Order choices smartly: try the most constrained variable first (the “minimum remaining values” heuristic).
    • 

  • Propagate constraints forward, e.g. remove a digit from a Sudoku row’s other cells once it’s placed.
    • 

  • Exploit symmetry so you don’t explore mirror-image solutions.
    • 



A cautionary tale: a badly written regular expression can backtrack exponentially on certain inputs. This “catastrophic backtracking” is a known way to freeze a server (ReDoS).







Interesting facts


    

  • The 8×8 board has 92 solutions, but only 12 are distinct once rotations and reflections are treated as the same.
    • 

  • The number of valid Sudoku grids is about 6.67×10²¹, yet a plain backtracking solver handles most puzzles in a fraction of a second.
    • 

  • Backtracking is depth-first search over an implicit tree: the tree is never stored, it exists only as the recursion call stack.
    • 

  • Maze generation by randomized depth-first search is backtracking too, which is why those mazes have long winding corridors and few short loops.
    • 

  • Backtracking versus dynamic programming: use backtracking to enumerate or find any solution; use dynamic programming when subproblems repeat and you only need an optimal value.
    • 







  
Closing remarks

  
Conclusion

  
Backtracking provides a systematic way to explore large sets of possible solutions while avoiding branches that already violate the problem constraints. The interactive examples demonstrate the same recursive pattern across different domains: define a state, generate a candidate, validate it, explore it and undo it when necessary.

  
The method is especially useful for constraint-satisfaction and combinatorial search problems. Its main limitation is the potential for exponential growth, which makes good state representation, early constraint checks, candidate ordering and other pruning techniques important. In robotics, the same reasoning pattern can support task sequencing and the exploration of alternative plans, although practical motion planning also requires geometric and collision checking.

  
Project takeaway: backtracking does not make an enormous search space disappear; it makes the search more selective by rejecting impossible partial solutions as early as possible.
